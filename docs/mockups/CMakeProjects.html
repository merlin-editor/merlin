1 · Several CMake projects in one folder
A folder can hold CMake projects that don't include each other, here firmware/, sim/ and tools/ with no CMakeLists.txt above them (CMake Tools #1374, 47 votes). Today merlin only sees one at the folder's top.

Finding them: every CMakeLists.txt with a project() call that no other one reaches through add_subdirectory, so a normal project with subfolders is still one project. Each has its own presets and build folder.

▣ The project comes first in the status bar, only when there's more than one. The preset and target after it are that project's, and so are Configure, Build, Run, Debug and the CMake view.

Follow the open file, on by default: opening sim/src/world.cpp makes sim the project. Picking one by hand turns following off until it's ticked again.

clangd gets the project's compile_commands.json, so it follows too. Run Task and Run and Debug list every project's tasks and programs, each with its project as the detail.

2 · The CMake view with several projects
A Projects section comes first, only when there's more than one: each project's state (green configured, red failed, grey not yet), its preset, and Configure. A click makes it the project, as the status bar's picker does, and the build, targets, tests and cache below are that project's. With one project the view stays as it is today.
One project with subfolders: the top CMakeLists.txt adds the others, so it's one project and nothing changes. No ▣ chip, no Projects section.
1project(shapes CXX) 2add_subdirectory(libs) # libs/CMakeLists.txt is part of it 3add_subdirectory(apps)
A project at the top and one it doesn't add, such as bootloader/ built on its own: both are listed, the top one first. Folders CMake builds into, and third_party/ or _deps/ under a build, aren't searched.
