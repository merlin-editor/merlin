3. Drawing a frame

wgpu notes · page 3

3.1 Recording, then submitting

A frame is recorded as a list of primitives, back to front, before anything reaches the GPU. Each glyph and picture is uploaded once into an atlas and named by its id; later frames only refer to it. The atlas is cleared when the font or the scale changes.

Because the list is plain data, the same frame can be drawn by a CPU backend where no adapter is found, and compared pixel for pixel in tests. The atlas keeps the two backends from drawing a glyph twice.

Figure 3. Frame time by number of primitives.

Uploads are batched per frame: an atlas that fills up is grown rather than split, which keeps one bind group for every glyph.

A file type from a plugin

The PDF plugin declares [[editors]] for .pdf, so the file opens as a tab like any other: in a group, beside code, back next time. The toolbar under the tab is the plugin's, drawn by merlin.

[[editors]] id = "pdf" title = "PDF" extensions = ["pdf"]

merlin scrolls, the plugin paints

The pages are a surface. merlin owns scroll and zoom and asks for tiles as they come into view, render-tile(page, x, y, w, h, scale), on the plugin's own thread. Until one comes back its place is hatched (page 4), and typing never waits for it.

Text you can use

The plugin says where each word is (set-text-boxes), so selecting, Copy, Find (amber, the current one darker) and the right-click menu are merlin's, as in a code tab. Other plugins' commands can act on the selection.

The cost, shown

The corner card is for this mock-up only: tiles in view and memory against the budget. The plugin's page in Settings shows its picture memory beside its wasm. A hidden tab drops its tiles; an idle one uses no CPU.
