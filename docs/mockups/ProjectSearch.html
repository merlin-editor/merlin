1 · Symbols from files you haven't opened

The palette's @ searches the whole project even when the active file isn't C/C++. Above, CMakeLists.txt is active and clangd wasn't running: typing @ started it for the search. The C/C++ plugin also starts when the project has a compile_commands.json, at the top or in build/, so a Make or meson project counts too, not only one with a CMakeLists.txt. While clangd is still indexing, a line under the results says how far it's got, and the status bar shows the same. Results that come in later are added as they arrive.

●No compile_commands.json, so clangd only knows open files. SCAN rows are from a quick look through the sources.Configure with CMake
Without a compile database, clangd has no background index. The plugin then reads the project's sources with its own lexer, finding functions, classes, structs, enums, unions, namespaces and macros, and marks those rows SCAN. The scan doesn't know types or overloads, and its container is only the Class:: written in front of the name. A file that's open in clangd (polygon.cpp here) shows clangd's symbol instead of the scan's. The scan runs once per search, from the plugin's thread, and skips excluded and ignored files. The amber line's link is the compile-commands bar's: Configure with CMake, or Set Include Folders without a CMakeLists.txt.

2 · Excluding from the Explorer and from Search
Right-click a file or folder in the Explorer:
Exclude from Project leaves it out of the Explorer, Quick Open, Search, @ symbols, Check Project and plugins' file lists. Exclude from Search Only keeps it in the Explorer and leaves it out of the rest. Both add a line to the project's exclusions (artboard 3), as third_party/. Add to .gitignore moves from the Source Control menu, where it stays too.

⊘ in the Explorer's title shows what's left out, dimmed, each marked with why: .gitignore, hidden or excluded. Right-clicking one offers Include in Project, which removes its rule, or opens .gitignore at the line that hides it. ⊘ is off at first, and each project remembers its state.
Search gets Files to include and Files to exclude, comma-separated globs, under Replace. src/ means the folder and everything in it, and *.h matches anywhere. Find in Folder… in the menu fills in the include box. The ⊘ in the exclude box turns the project's exclusions and .gitignore on or off for this search. With them on, the count says how many files were skipped. The palette's / text search uses the same exclusions, with no boxes of its own.

3 · The exclusions, in Settings › Files
One list everything follows, so the Explorer, Search and symbols always agree. User sets it for every project, and Workspace adds to it for this one. A User line shows as from User and can only be removed there. In TOML:
# .merlin/settings.toml [files] exclude = ["third_party/", "**/*.generated.h"] [search] exclude = ["docs/api/"]
Plugins see the same rules: list-files already skips them, and a new is-excluded(path) lets a plugin check a path it found another way, such as one clangd returned.
C/C++plugin setting
Keep clangd out of excluded folders
Writes an Index: Background: Skip block for them into the project's .clangd, between merlin's comment lines, leaving the rest of the file alone. Indexing is quicker, but Go to Definition into those files only works once they're open.
clangd can't be told on its command line what to skip, only through a .clangd file. So this is off at first, and when it's on, its notice says which file it changed.
