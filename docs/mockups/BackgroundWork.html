1 · Find counts in the background
A large file's matches are counted on a few background threads, so typing in Find never waits. Above, a 342 MB log: 1,204 so far with a spinner, and a thin line along the box's foot for how far through the file the count has got (38%). The scrollbar's match marks fill in from the top as the count passes them. ↑, ↓ and Enter go to the next match straight away: they search from the cursor and don't need the count. Typing again starts a new count; a query grown from the last one counts only where the last matched, so it's usually done before the next key. A file under about 8 MB is counted at once, as now, and never shows this.

4 · Turning word wrap on in a large file
Wrapping a 342 MB file takes about half a second, now done in the background. The view wraps at once around the screen; the rest of the file counts as a row a line until it's done, so the scrollbar's thumb may shift a little when it finishes. The status bar shows Wrapping 41% with a spinner meanwhile, as it does for a language server's indexing. Resizing the window with wrap on does the same, once the resize stops. The git gutter's diffs and the outline's symbols also move to the background, with nothing new to show: they appear when ready, as they do now.
