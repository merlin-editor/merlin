1 · The language item opens its card
Rust at the end of the status bar is the language item, as in VS Code and Zed. Its { } is green while every server is fine, a spinner while one works, amber when one has a problem and red when one stopped.

A click opens this card over the status bar. Each row comes from the plugin for the file's language: a server with its state, memory and Restart, then whatever else the plugin says, such as format on save and the file's tests. Esc or a click elsewhere closes it.

The plugins no longer each get a side bar view. The rail keeps Explorer, Search, Source Control, Tests, Run and Debug, Outline and Plugins. Problems stay in the bottom panel, so the cards don't repeat them.

For plugin authors, one new host call replaces the panel for a language plugin:
set-language-status(language, items)
where each item has a name, a state (ready, busy, warning, error), a detail, an optional progress from 0 to 100, and an optional button: its label and the command it runs. The card is built from them, so every language looks the same. A plugin can still keep a panel for something else; the shared LSP client stops making one.
