Your own, in launch.toml
TOlaunch.toml
1[[debug]] 2name = "merlin on notes" 3program = "target/debug/merlin" 4args = ["~/notes"] 5build = "cargo build" # run first 6env = { RUST_LOG = "info" } 7console = "terminal" # or "debug" 8 9[[debug]] 10name = "attach" 11attach = "merlin" # or a pid
Written like tasks.toml, with completions for its keys. build is a task's name or a command, run first. console = "terminal" runs the program in a Terminal tab, so it can read what you type; the default prints into the Debug Console. A language plugin may add its own keys, such as Python's module.

⚠Debugging Rust needs lldb-dap or CodeLLDB, and merlin found neither. lldb-dap comes with LLDB:

Looked on PATH and in VS Code's extensions for CodeLLDB. gdb 14 and later speak the same protocol, so it's offered when it's there.
merlin doesn't download debuggers. Each language plugin names the ones it knows and the command to install them: lldb-dap, CodeLLDB and gdb for Rust and C++, debugpy for Python, js-debug for JavaScript. Choose the Path… opens Settings at debug.rust.adapter.

A language plugin adds its debugger
TOplugins/go/plugin.toml
8[permissions] 9processes = ["gopls", "dlv"] 10 11[[debuggers]] 12id = "delve" 13name = "Delve" 14languages = ["go"] 15command = ["dlv", "dap"] 16install = "go install …/dlv@latest" 17launch = { mode = "debug" }
Any plugin can bring a debugger in its manifest, the way it brings a language: which languages, the command, other names to look for, and how to install it, which the "no debugger" notice shows. Being in the manifest, merlin knows it before the plugin runs. launch is sent with every start.

The Debugger plugin does for debuggers what the lsp plugin does for language servers: it starts each one the plugins declare and speaks the protocol, so a new language needs no code to be debugged, only the manifest. It's a plugin like the others, so it can be turned off, or replaced.
