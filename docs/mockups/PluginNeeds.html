8 · Versions decide

The Versions tab gets a Systems column. Install picks the newest that fits; here 0.3.0 dropped Windows, so Windows gets 0.2.4.

0.3.0API 0.15Linux, macOSnot for Windows
0.2.4API 0.15allInstall picks this
0.2.3API 0.14allolder API

A processor shows the same way: "x86_64 only" on an ARM Mac.

9 · A linked plugin that says no

One linked with merlin plugin install <dir> whose manifest leaves this system out. It isn't loaded, and its page says why.

⊘
perf says it works on Linux, and this is Windows, so it isn't loaded. Its systems are in plugin.toml.

A debugger or program left out for this system is quietly skipped: not tried, and not listed as missing in 2 or 4.

Dependencies (12.4)

10 · Installing with what it needs

One card for everything that installs. Each plugin with what it asks for; one button.

Install Go?

Go needs Language Servers, which isn't installed. Both install together.
GO
Go 0.2.0
⚠ Starts gopls and dlv, outside the sandbox
LS
Language Servers 0.3.1 needed by Go
✓ Reads and changes open files
CancelInstall Both

11 · When versions don't agree

One version of each plugin at a time. If none satisfies everyone, nothing installs, and the card says who wants what.

Go can't be installed yet

Go needs Language Servers 0.3 or later. Rust needs 0.2, and no version is both.
When Rust has a version that works with Language Servers 0.3, Go can install.
Open Rust's PageClose

13 · Uninstalling one that others need

Asks first, and names them. They stop starting until it's back.
